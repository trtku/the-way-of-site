# セットアップ手順（最初の1回だけ・開発側）

これを終えると、以後は「シートを直す → ボタンを押す」だけで運用できます。
所要 30〜60分。費用は **0円**（無料枠の範囲）。

---

## 0. 前提

| もの | 状態 |
|---|---|
| Driveフォルダ `2026_WEB` | 作成済み |
| スプレッドシート `THE WAY OF → CMS` | 作成済み・実データ入り |
| このサイト一式 | `02_サイト一式` に入っている |

---

## 1. スプレッドシートの共有設定

スプレッドシート右上［共有］→ 一般的なアクセス →
**「リンクを知っている全員」＋「閲覧者」**

> これで `gviz` 経由の読み取りができるようになります。
> 「ウェブに公開」は**不要**です。編集権限は招待した人だけのままです。

## 2. GitHubリポジトリを作る

```bash
cd 02_サイト一式/twayof-site
git init && git add -A && git commit -m "first"
gh repo create the-way-of-site --private --source=. --push
```

> **公開（public）にすると GitHub Actions の実行時間が無制限**になります。
> 非公開のままでも月2,000分の無料枠があり、この規模なら十分足ります。

## 3. Drive APIキーを作る（画像取得用）

1. https://console.cloud.google.com/ でプロジェクトを作る
2. 「APIとサービス」→ ライブラリ → **Google Drive API** を有効化
3. 「認証情報」→ APIキーを作成
4. **キーの制限**: APIの制限 → Google Drive API のみ

5. `01_画像入稿` フォルダを「リンクを知っている全員が閲覧可」にする

> APIキーを入れなくてもビルドは通ります（`test-images/` の仮画像が使われます）。
> 先にサイトを立ち上げて、あとから入れても大丈夫です。

## 4. GitHub の Secrets を入れる

リポジトリ → Settings → Secrets and variables → Actions

| 名前 | 値 |
|---|---|
| `SHEET_ID` | `1VK_dI38YlibmRUMcesN7bc84lq6xYuEZesH4iRxTQao` |
| `DRIVE_IMAGE_FOLDER_ID` | `1_Ge385mMiV8r0A7W8xyEJbM7UDsxEYK6` |
| `GOOGLE_API_KEY` | 手順3で作ったキー |
| `SITE_URL` | 本番URL（例: `https://the-way-of.pages.dev`） |
| `CLOUDFLARE_API_TOKEN` | 手順5で作る |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflareダッシュボード右下 |

## 5. Cloudflare Pages

1. https://dash.cloudflare.com → Workers & Pages → Create → Pages
2. プロジェクト名 **`the-way-of`**（`build.yml` の `--project-name` と合わせる）
3. API トークン: My Profile → API Tokens → Create →
   テンプレート **Edit Cloudflare Workers**（または Pages:Edit 権限）

> 無料枠: ビルド500回/月、1サイト2万ファイル、帯域無制限。
> 月1更新＋日次チェックなら月35回前後です。

## 6. スプレッドシートに「サイトに反映」ボタンを付ける

1. スプレッドシート → 拡張機能 → Apps Script
2. `apps-script/Code.gs` の中身を貼る
3. プロジェクトの設定 → スクリプト プロパティ に

   | 名前 | 値 |
   |---|---|
   | `GITHUB_OWNER` | GitHubのユーザー名 |
   | `GITHUB_REPO` | `the-way-of-site` |
   | `GITHUB_TOKEN` | Fine-grained token（対象リポジトリのみ・**Actions: Read and write**） |

4. 保存 → シートを開き直す → 上に［サイト］メニューが出る

---

## 7. 動作確認

- [ ] ［サイト］→［サイトに反映する］で Actions が走る
- [ ] 3〜5分でサイトが更新される
- [ ] `slug` にわざと大文字を入れて反映 → **失敗し、サイトは古いまま**
- [ ] 戻して反映 → 成功

最後のテストが通れば、「壊れたものは公開されない」仕組みが効いています。

---

## ローカルで動かす

```bash
npm install
cp .env.example .env     # SHEET_ID はすでに入っている
npm run sync             # シート → data/content.json
npm run sync:images      # 画像（APIキーが無ければ test-images/ を使う）
npm run dev              # http://localhost:4321
```
